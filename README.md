# 校园网自动连接

适用于使用 `http://10.2.5.251/` 门户、且认证配置与已验证网段一致的 Windows 校园网用户。使用系统自带的 Windows PowerShell 5.1，无需安装 Python 或浏览器扩展。其他学校或不同认证配置需要另外适配。

## 分享与接收

从 GitHub 下载时，可点击 **Code → Download ZIP** 下载整个项目，完整解压后运行 `Configure.cmd`。也可以下载仓库中的 `CampusAutoConnect-分享版.zip`。

将 **CampusAutoConnect-分享版.zip** 通过微信、QQ、邮件或网盘发送给同学即可。分享包只包含源程序、说明和离线测试，不包含分享者的个人配置、凭据或日志。

接收者先把压缩包**完整解压到一个文件夹**，再双击 `Configure.cmd`，填写自己的账号、密码并选择运营商。不要直接在压缩包中运行，也不要单独发送或移动 `Configure.cmd`；它需要同目录的脚本文件。

不要把 `%LOCALAPPDATA%\CampusAutoConnect` 中的个人配置及凭据打包发送。每位接收者都应在自己的电脑上重新配置。

## 首次使用

1. 在 Windows 的 Wi-Fi 设置中，给学校 Wi-Fi 勾选“自动连接”。有线网络则保持网线连接。
2. 双击本目录的 **Configure.cmd**，打开配置窗口。
3. 输入平时网页登录所用的账号、密码，选择相同运营商。已确认当前登录表单提供：中国电信、中国移动、中国联通、校园网。若填写的账号本身已含 `@cmcc` 等后缀，选“账号已含后缀 / 不添加”即可。
4. 保持勾选“登录当前 Windows 账户后，在后台自动连接校园网”，点击 **保存并启动**。
5. 稍等后点击“刷新状态”。如果原本已在线，会显示无需登录；这不代表已经验证了新保存的密码。真正的自动登录需在下一次自然断线或重启后验证。

之后可以关闭配置窗口。登录 Windows 后，后台约每 60 秒检查一次；休眠恢复或网络重新接通后也会继续检查。网络请求超时会等待重试，不会反复弹出浏览器或命令窗口。

当前版本通过系统默认网络路径检查和认证。如果同时连接校园网线与校园 Wi-Fi，一条已认证不代表另一条也已认证。使用网线时可关闭 Wi-Fi，避免显示另一条连接未联网的提示。

## 查看状态和停用

- 双击 **Check-Status.cmd**：只读取校园网当前认证状态，不发送账号密码。
- 再次打开 **Configure.cmd**：可修改密码、刷新后台最近状态，或点击“取消自启动并停止后台”。停用不会注销现有网络，正在进行的网络请求可能需要几秒结束。
- 服务器明确拒绝认证后，程序会暂停后续登录尝试。确认账号、密码、运营商和账户状态后，重新保存并启动即可恢复。
- “保存配置”只写入配置及自启动设置，不会新启动后台；已在运行的后台会读取新配置。取消勾选自启动并保存，也会请求现有后台停止。“保存并启动”在未勾选自启动时仍可供本次会话使用。

## 文件和凭据

程序安装到当前用户的 `%LOCALAPPDATA%\CampusAutoConnect`，配置窗口会复制主脚本；安装后移动原始项目目录不会影响已安装的后台程序。无需管理员权限。

- `settings.json`：认证地址、完整账号及检查间隔约定。
- `credential.xml`：通过 Windows 用户账户加密的凭据，不能直接复制到其他电脑或 Windows 账户使用。
- `status.json`、`connection.log`：最近状态及简短日志，不记录账号密码或登录请求地址。
- `auth-block.json`：记录上次认证被拒绝，防止持续重试错误密码。
- 当前用户的启动文件夹中有 `CampusAutoConnect.lnk`，用于进入 Windows 后启动后台。

密码仅在本机配置窗口输入。认证通信沿用学校网页现有的 HTTP 接口；本地加密保存不等同于传输加密。

## 实现与验证范围

程序先读取 `/drcom/chkstatus`。确认未认证后，解析门户分配的 IP、MAC 和当前网段的登录方式，再使用页面已核实的 Portal 参数认证。门户地址必须与本机网卡匹配；不跟随 HTTP 重定向，不执行服务器返回的 JavaScript。已在线时不重新认证，也不调用注销接口。

工具支持当前确认的 Portal 方法 1 和无需验证码的表单。如果学校改变认证流程、需要验证码、门户提供的地址与本机网卡不同，程序会停止本轮提交并显示原因。状态中的“在线”表示校园网认证服务器认为已认证，不能保证所有外部网站都能访问。

开发验证包括：实际只读检测当前门户、确认表单及网段匹配，以及模拟响应下的登录/拒绝/重试测试。真实账号密码登录仍需在本机配置后、下一次需要认证时验证。

供维护使用：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests.ps1` 运行离线测试；`diagnose.ps1` 只读检查服务器配置与网卡匹配，不读取凭据。
